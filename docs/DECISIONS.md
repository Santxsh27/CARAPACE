# CARAPACE v3.1 implementation decisions

1. **Reuse the current repository.** The v3.0 attachment asked for a new TypeScript repository, but the user's explicit instruction is to keep and edit the existing CARAPACE Python repository. This preserves the working FastAPI, Gemini and test foundations while retiring the old homepage framing.
2. **Local signatures are development signatures.** Ed25519 signs canonical bank-order and decision JSON. The private key is persisted in a local protected file to survive restart. This proves tampering in the demo; it is not a production bank KMS or an independently administered bank signature.
3. **Put the first gate and ledger in one transaction.** The local gate refuses HOLD, unresolved WARN, expired orders, changed signatures and repeat submissions before inserting a synthetic transfer in SQLite. This gives a strong, testable Milestone 1 invariant without falsely claiming that a separate Bank of Anthos database can be committed atomically with CARAPACE's store.
4. **Keep image grounding honest.** Gemini can examine a supplied screenshot, but Gemini's own transcription is not independent OCR. The demo therefore supplies visible fixture text alongside the generated image; image-only risk signals may raise a warning or HOLD, but unsupported values cannot establish an ALLOW. Cloud Vision OCR and independent value grounding are later integration work.
5. **Fail closed on provider error.** If the configured context provider fails, the local bank gate records HOLD with a named reason. A configured provider status is never presented as proof that a live call succeeded.
6. **Use a measured live demo model.** On 25 September 2026, Gemini 3.6 and 3.8 Flash returned intermittent `503 UNAVAILABLE` for artificial image inputs, while the listed Gemini 3.5 Flash Lite returned valid structured results for both the refund and bill cases. The local demo uses 3.5 Flash Lite and still fails closed on any later provider error. This is an operational choice, not a claim that one model is universally superior.
